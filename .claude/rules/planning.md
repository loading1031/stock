# 기획 문서 규칙

## 문서 구조

```
docs/planning/
├── plan.md        전체 기획 (기준 문서). 다른 문서는 여기서 링크된다
├── strategy.md    운영 전략 (plan.md 3.6의 상세)
├── <주제>.md      새 주제 기획 (plan.md의 해당 절에서 링크)
├── backlog.md     다음 기획 후보
└── log.md         결정 이력 (최신이 위)
```

- 새 주제는 `plan.md`의 한 절로 충분하면 거기에 쓰고, 한 화면을 넘으면 `<주제>.md`로 분리한 뒤 `plan.md`에는 요약 3~5줄과 링크만 둔다.
- 파일명은 kebab-case 영어. 본문은 한국어.

## 새 주제 문서 템플릿

```markdown
# <주제>

- 작성일: YYYY-MM-DD
- 상태: 초안 | 검토 중 | 확정
- 관계: plan.md <절 번호>의 상세. 관련 문서: <링크>

## 결론
한두 문장. 무엇을 하기로 했는가.

## 결정 사항
| 항목 | 결정 | 이유 |

## 상세
(표, 흐름, 다이어그램 우선. 문장으로 구조를 설명하지 않는다)

## 데이터 모델 영향
추가·변경되는 테이블과 컬럼. 없으면 "없음".

## 다른 문서에 반영할 곳
- plan.md <절>: ...
- strategy.md <장>: ...

## 확인이 필요한 것
- [ ] ...

## 출처
- [제목](URL)
```

## 작성 원칙

- 결론을 먼저 쓴다. 각 절의 첫 문장이 그 절의 답이다.
- 구조가 있는 내용(흐름, 상태, 비교)은 표나 다이어그램으로 쓴다.
- **사실은 확인한 것만 쓴다.** 블로그·2차 자료에서 온 수치는 "(2차 자료 기준)" 또는 "**검증하지 않음**"을 붙이고 확인 필요 항목에 넣는다. 출처 URL을 남긴다.
- 사용자가 결정하지 않은 것은 "제안"으로 쓴다.
- 수치 파라미터는 `strategy.md` 17장처럼 한 표에 모으고 "가정값"임을 밝힌다.

## 동기화 규칙

하나의 결정이 여러 곳에 반영된다. 한 곳만 고치지 않는다.

| 바뀐 것 | 함께 고칠 곳 |
|---|---|
| 기능·아키텍처 | plan.md 해당 절, 데이터 모델(5장), 마일스톤(7장), 확인 필요(8장) |
| 운영 전략 | strategy.md 해당 장, **0장 Mermaid 먼저**, 그다음 시각화 문서의 "운영 전략 워크플로" |
| 테이블 | plan.md 5장 또는 strategy.md 18장, 시각화 문서 "데이터 모델" |
| 용어 | plan.md 1장 용어 설명, strategy.md 머리말, CLAUDE.md 용어 |
| 결정된 사항 | CLAUDE.md "결정된 사항" 표 |

- 시각화 문서는 Claude Docs 도구로 고친다. 다이어그램을 고치면 스크린샷으로 렌더링을 확인한다.
- 시각화 문서를 이번에 고치지 못하면 `backlog.md`의 "동기화 빚"에 적는다.
- 문서끼리 수치나 용어가 어긋나면 고치기 전에 사용자에게 알린다.
- 사용자가 직접 편집한 흔적(예상과 다른 디스크 변경)이 있으면 덮어쓰지 말고 무엇이 다른지 먼저 보고한다.

## backlog.md 형식

```markdown
## 후보
| ID | 주제 | 왜 필요한가 | 선행 | 우선순위 |
| B-07 | 알림 채널 | 토큰 실패·리셋·만료 알림 수단 미정 | — | P1 |

## 진행 중
## 완료
| ID | 주제 | 결과 문서 | 날짜 |

## 동기화 빚
- [ ] 시각화 문서 "데이터 모델"에 global_* 테이블 없음
```

- ID는 `B-<번호>`, 번호는 재사용하지 않는다.
- 우선순위: P0 = 다음 마일스톤 착수 전에 필요, P1 = 해당 마일스톤 안에서 필요, P2 = 나중.

## log.md 형식

최신 항목이 위에 온다.

```markdown
## YYYY-MM-DD <유형> | <제목>
- 결정: ...
- 바뀐 문서: plan.md 3.2, strategy.md 15장
- 남은 것: B-12로 이관
```

유형: `decide`(결정), `update`(수정), `revert`(결정 번복), `sync`(동기화만).
