# /backlog — 다음 기획 주제 고르기

`docs/planning/backlog.md`를 보고 다음에 기획할 주제를 고르거나, 새 후보를 추린다.

## 사용법

```
/backlog              — 후보 목록을 우선순위 순으로 보여 주고 다음 주제를 추천
/backlog add <주제>   — 새 후보 추가 (왜 필요한지, 선행, 우선순위 함께)
/backlog pick <ID>    — 해당 항목을 "진행 중"으로 옮기고 논의 시작
/backlog sweep        — plan.md 8장, strategy.md 19장의 확인 필요 항목과 대화에서 나온 주제를 훑어 후보를 새로 추림
```

## 실행 절차

### 기본 (인자 없음)
1. `backlog.md`를 읽는다.
2. "진행 중" 항목이 있으면 먼저 그것을 알린다. 진행 중 항목은 1~2개를 넘기지 않는다.
3. 후보를 P0 → P1 → P2 순으로 보여 주고, 다음 주제 하나를 이유와 함께 추천한다.
   - 추천 기준: 다음 마일스톤 착수를 막는가(P0) → 다른 항목의 선행인가 → 결정만 하면 되는가(조사가 적은가)
4. "동기화 빚"이 있으면 함께 알린다.

### add
1. 같은거나 겹치는 후보가 있는지 확인한다. 있으면 합칠지 묻는다.
2. 다음 ID를 붙여 "후보" 표에 추가한다.
3. 지금 논의 중인 주제가 있으면 그 주제로 돌아간다. 새 후보를 바로 파고들지 않는다.

### pick
1. 항목을 "진행 중"으로 옮긴다.
2. 관련 문서 절(plan.md, strategy.md)을 읽고, 이미 정해진 것과 열린 질문을 정리해 사용자에게 보여 준다.
3. 조사가 필요하면 출처를 열어 확인한다. 열린 질문은 한 번에 1~3개씩 사용자에게 묻는다.
4. 결정이 모이면 `/spec`을 제안한다.

### sweep
1. `plan.md` 8장, `strategy.md` 19장, 각 문서의 "제안"·"검증하지 않음" 표시를 훑는다.
2. 기존 후보와 겹치지 않는 것만 후보로 제안하고, 사용자가 고른 것만 추가한다.

## 규칙
- backlog.md 형식은 `.claude/rules/planning.md`를 따른다.
- 백로그를 고쳤으면 `log.md`에는 쓰지 않는다. log는 결정만 기록한다.
- 커밋은 `/spec`과 함께 묶는다. 백로그만 바뀌었으면 `/commit`으로 `docs: 백로그 갱신`.
