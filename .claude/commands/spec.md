# /spec — 결정된 내용을 기획 문서에 반영

논의에서 **사용자가 결정한 내용**을 기획 문서에 쓰고, 관련 문서를 동기화하고, 이력을 남긴 뒤 커밋까지 한다.

## 사용법

```
/spec <주제>          — 결정 사항을 반영 (plan.md 절 또는 docs/planning/<주제>.md)
/spec check           — 문서 간 용어·수치·테이블 불일치 검사만
```

## 실행 절차

### 1. 반영할 내용 확정
1. 이번 대화에서 **결정된 것 / 제안만 된 것 / 열린 질문**을 나눠 사용자에게 보여 준다.
2. 결정된 것만 "결정"으로 쓴다. 제안은 "제안"으로, 열린 질문은 확인 필요 항목으로 간다.
3. 사용자 확인을 받는다. 확인 없이 쓰지 않는다.

### 2. 문서 작성
1. `plan.md`의 한 절로 충분한지, `<주제>.md`로 분리할지 정한다 (`.claude/rules/planning.md`).
2. 분리하면 템플릿으로 새 문서를 만들고, `plan.md`에는 요약과 링크를 둔다.
3. 디스크의 파일이 마지막으로 읽은 내용과 다르면 덮어쓰지 말고 차이를 먼저 보고한다.

### 3. 동기화
`.claude/rules/planning.md`의 동기화 표에 따라 함께 고칠 곳을 모두 고친다.
- 운영 전략이 바뀌면 `strategy.md` 0장 Mermaid → 시각화 문서 순서로 고친다.
- 시각화 문서의 다이어그램을 고쳤으면 스크린샷으로 렌더링을 확인한다.
- 이번에 못 고친 곳은 `backlog.md` "동기화 빚"에 적는다.

### 4. 기록
1. `log.md` 맨 위에 항목을 추가한다 (결정, 바뀐 문서, 남은 것).
2. `backlog.md`: 해당 항목을 "완료"로 옮기고, 논의에서 새로 나온 주제는 "후보"에 추가한다.
3. `CLAUDE.md`의 "결정된 사항" 표에 들어갈 수준의 결정이면 갱신한다.

### 5. 커밋
`/commit` 규칙으로 `docs:` 커밋을 만든다. 메시지에는 무엇을 결정했는지 쓴다 (예: `docs: 알림 채널을 텔레그램 봇으로 결정`).

### check
1. `docs/planning/` 전체와 `CLAUDE.md`를 읽는다.
2. 아래를 찾아 보고한다. 고치지는 않는다.
   - 같은 대상의 용어·수치·시간이 문서마다 다른 곳
   - plan.md 5장·strategy.md 18장과 시각화 문서 데이터 모델의 테이블 차이
   - strategy.md 0장 Mermaid와 본문 장의 흐름 차이
   - "단계"라는 말이 남은 곳
   - 확인 필요 항목 중 이미 확인된 것
3. 발견한 것을 `backlog.md` "동기화 빚"에 넣을지 묻는다.

## 규칙
- 사용자가 결정하지 않은 것을 결정으로 쓰지 않는다.
- 사실은 확인한 출처만. 확인 못 한 수치는 "검증하지 않음"과 함께 확인 필요 항목으로.
- 한 번의 /spec은 백로그 항목 하나를 닫는다. 여러 주제를 섞지 않는다.
